CMAI2100F1 OCAP 이식 결과 (기준: 이번에 첨부한 F1 / F2 v2.7.1)

1. 적용 결과
F1 원본을 기반으로 OCAP 관련 코드만 추가했습니다.
F2의 FAI / Cosmetic 화면, 100개 코드 설정, 5페이지 x 20개 구성,
불량률 및 연속 Lot 조건, 이력의 적색 표시, CSV 저장, Lot 스냅샷,
알람 대기열 및 알람 상세/Lot ID 표시를 이식했습니다.

2. F2와 완전히 동일하게 복사한 부분
OCAPFAI.cpp/.h, OCAPCosmetic.cpp/.h, OCAPSelect.cpp/.h,
OCAPManager.cpp/.h, OCAPRules.h, Run/System/OCAP_Data.ini:
10개 파일 전체의 바이트가 F2와 동일합니다.
OCAP 전용 다이얼로그 3개, 메인 OCAP 버튼 리소스 및 OCAP ID도 F2와 동일합니다.
DataManager의 OCAP 초기화/INI 읽기 함수와 LogFile의 OCAP CSV 함수도 F2와 동일합니다.
공유 파일에는 OCAP 선언/초기화/호출/프로젝트 항목만 선택하여 추가했습니다.

3. 그대로 복사하지 않은 연결 부분 (기존 F1 로직 보존 목적)
SequenceMain.cpp / Set_LotEnd:
F2는 Lot ID 불일치, 빈 Lot ID, 이미 종료된 Lot일 때 함수 전체를 return합니다.
F1에서는 이 조건을 OCAP_QueueLot 호출에만 적용했습니다.
따라서 OCAP에 등록되는 조건은 같으며 기존 F1의 Lot 종료/MES/로그 처리는 유지됩니다.

Inspector.cpp:
F2의 OCAP 관련 표시가 있는 지연/중복 COMPLETE 응답 차단 코드는
검사 응답 처리 함수 자체를 return하므로 이식하지 않았습니다.
Inspector.cpp 전체는 F1 원본과 바이트 단위로 동일합니다.
OCAPManager의 Lot 스냅샷 및 중복 등록 방지 코드는 F2 그대로입니다.
따라서 'OCAP 주변 코드를 전부 한 글자도 다르지 않게 복사'한 결과는 아닙니다.
검사 응답을 차단하는 동작까지 포함한 모든 예외 상황의 동작 동일성은 보장하지 않습니다.
이는 다른 검사/시퀀스 로직을 변경하지 말라는 요청을 우선한 부분입니다.

4. 보존 범위
F1의 모션/축/IO/통신/검사 판정/MES 및 일반 로그 코드,
장비 설정, 레시피, 기존 리소스와 프로젝트 출력 설정을 유지했습니다.
F2의 NEW_FINAL 정의, 하드웨어 차이, 시뮬레이션 통신, 표준 로그 추가 등은 제외했습니다.
ErrorDlg의 Job 미진행 시 Lot ID 초기화 조건은 OCAP 알람 9181~9188에 한해서만 예외를 추가했습니다.
F2의 다른 ErrorList 설정은 가져오지 않았으며 OCAP 알람 문구는 F2와 같이 코드에서 지정합니다.

5. 검증
- 기존 파일 261개 중 246개: F1 원본과 바이트 단위 동일.
- 기존 파일 15개: OCAP 관련 연결/리소스/프로젝트 항목만 변경.
- 신규 OCAP 파일 10개: F2와 바이트 단위 동일.
- 공유 C++/프로젝트 파일은 기존 줄을 모두 보존.
  예외: OCAP 알람에 대한 Job 미진행 시 Lot ID 초기화 조건 1줄 변경.
- 기존 리소스는 그대로 유지하고 OCAP 리소스만 추가한 것을 검증.
- OCAP 컨트롤 ID 일치/기존 ID 충돌 없음, 프로젝트 등록과 XML 형식 검증 완료.
- Visual Studio 2010/MFC가 없는 Linux 환경이므로 실제 빌드 및 장비 구동 검증은 수행하지 못했습니다.
